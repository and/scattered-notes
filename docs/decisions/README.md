# Decision log

One short file per feature, written when it is built, saying why it was built and why it was built this way. Later, two or three of these can be turned into a case study.

Name files `YYYY-MM-DD-short-name.md`. Keep each to about half a page. Write in your own words; the drafts here are starting points.

## Template

```
# Title: what changed, in plain words

Date, commits

## Problem
What was missing or annoying, in one or two sentences. Whose problem is it?

## Evidence
What was actually seen: a screenshot, a number, a quote from real use.

## Options
Two or three ways it could have been done, and why each was kept or rejected.

## Decision
What was built, and the one reason it won.

## Result
What changed. A measurement if there is one. Say when something was not measured.

## Cost and next
What was given up. What would come next.
```
