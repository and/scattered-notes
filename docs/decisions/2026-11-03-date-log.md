# Changing a to-do's date, with a history

2026-11-03. Commit `43c4914`.

## Problem
Dates on to-dos only came from words in the note ("tomorrow") or from markers the app wrote. There was no way to give an undated to-do a date, or to move an overdue one, and no record of how often a task slipped.

## Evidence
Overdue and undated items piled up on the Dashboard with no action available on them. A later request showed the same need in the note's Agenda column, so the date control exists there too.

## Options
Where to keep the history of changes:
1. In each note's front matter. Rejected: every reschedule rewrites the note header and the header keeps growing.
2. In the app's local storage only. Rejected: it would not reach the iPhone and would be lost if app data were wiped.
3. A file next to the notes, one per device. Chosen.

How to store the date itself: reuse the date marker already written at the end of a line (`📅 2026-11-02`). It is the one place every version of the app already reads, so no new storage was needed.

## Decision
A change rewrites the line's marker and appends one JSON line to `.date-log-<device>.jsonl`. Each device writes only its own file, so iCloud never has two devices changing one file. Reading merges all the files, drops repeated ids and sorts by time, which gives the same history on every device. This is a small case of a grow-only set, a data type built so copies can merge without conflicts.

## Result
The Mac Dashboard, the Agenda column and the iPhone can set or change a date, and each shows the last five changes. Unit tests cover writing the marker, reading the log back, skipping a half-written last line and merging two devices.

## Cost and next
- History is matched by the line's words, so rewording a to-do leaves its earlier history behind.
- There is no "clear date" action, because saving would restore the old marker.
- The Windows and Android versions read the new date but do not write or show the log yet.
